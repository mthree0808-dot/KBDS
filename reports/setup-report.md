# 하네스 구축 리포트

확인일: 2026-09-28

상태: **하네스 구현 및 로컬 검증 완료 / 실제 화면 제작 종단간 검증 미실행**

## 작업 근거

사용자가 제공한 MO 디자인 시스템과 Templates 페이지를 Figma MCP로 읽었습니다. 품질 우선순위는 사용자의 답변인 “템플릿과 다른 배치·폰트·간격”에 맞췄습니다. 빈 작업 폴더에서 시작했으며 기존 두 하네스의 코드나 결과물은 제공되지 않아 비교 분석하지 않았습니다.

원본 컴포넌트 페이지 6개에서 1,147개 component/component set 항목, 원본이 링크한 Graphic System Icon에서 126개 항목을 수집했습니다. 총 1,273개 항목은 component 1,140개와 set 133개이며 모두 독립 UI 종류라는 뜻은 아닙니다. 변수 584개, 텍스트 스타일 114개와 collection/paint/effect 정보도 저장했습니다.

템플릿 공통·안내·약관·선택·바텀시트의 후보 목록을 수집했습니다. 대표 3개 화면의 구조를 읽고 PNG를 직접 확인했습니다. `10638:16306` 헤더와 타이틀 화면은 새 수집기로 42개 노드 전체를 수집·병합했습니다. 나머지 모든 템플릿의 깊은 분석이 끝났다는 의미는 아닙니다.

## 구현

- 작업 규칙, 화면별 재조회·매핑·제작·복구·검증 절차
- 페이지 단위 Figma 읽기 스크립트 생성과 응답 병합 검사
- 원본 키/해시/요구사항 기반 제작 전 검사
- 참조 자동 레이아웃·인스턴스·단일 스타일 텍스트를 사용하는 제한된 제작 스크립트 생성기
- 실제 산출물 재수집 결과와 계획/참조 비교
- 현재 스크린샷 검수 근거가 없으면 PASS 금지
- 작업 근거와 오류를 포함하는 Markdown/JSON 리포트

## 발견 오류 및 대응

|사항|대응/상태|
|---|---|
|Figma 큰 응답이 약 20KB에서 잘림|컴포넌트·토큰·스타일·노드를 분할 재조회하고 완전한 JSON만 저장|
|Foundations, T01~T04 별도 페이지가 비어 있음|실제 Templates 페이지 하위 화면을 근거로 사용|
|일부 원본 컨테이너 gap 9·10에 토큰 연결 없음|비표준 규칙으로 자동 채택하지 않고 제작 전 차단|
|System Icon이 다른 파일로 이동|원본 텍스트의 하이퍼링크로 Graphic 출처 확인·키 수집|
|일부 remote/오래된 변수 참조|수집기가 alias와 실제 key를 조회; 미해결 의존성은 통과 금지|
|PowerShell npm.ps1 실행 정책 제한|환경 설정 변경 없이 `node --test`로 검사|

## 검증 범위

실제 Figma에서 읽기 수집기 실행을 확인했습니다. `node --test` 결과 **25개 통과, 0개 실패**입니다. 로컬 테스트는 잘린 응답, 수집 누락/중복, 원본 쓰기 방지, 근거 해시 변경, 미연결 간격, 요구사항 누락, 임의 컴포넌트, 잘못된 모드, 제작 코드 문법, 시각 검수 누락/노후화, 간격·폭 변경, 토큰 연결 누락, 외부 토큰, 이미지 삽입, 부분 제작 실패 등을 검사합니다. 최신 테스트 결과는 `node --test`로 재현할 수 있습니다.

기획서 및 산출물 URL이 제공되지 않아 원본 파일에는 디자인 노드를 생성·수정하지 않았습니다. 제작 스크립트의 실제 import/폰트/모드/레이아웃 실행과 산출물 시각 검수는 첫 실제 작업에서 검증해야 합니다. MCP 수집기 검증과 로컬 테스트 통과를 디자인 결과물 품질 검증으로 대체하지 않았습니다.

컴파일러가 처리하지 못하는 SLOT·중첩 override·혼합 스타일·절대 배치 등은 전용 스크립트와 동일한 검수 절차가 필요합니다. CLI가 시각적 완성도를 자동으로 판정하지는 않습니다.

## 다음 작업 입력

기획서(와이어프레임) 노드 URL, 산출물을 추가할 페이지/프레임 URL. 이 두 입력으로 화면별 템플릿 선정 및 실제 디자인 제작을 시작합니다.
